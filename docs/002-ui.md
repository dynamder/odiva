# 002 UI

一个普通的聊天窗口。三层带：联系人行、会话区、输入区。

## 规则

- **一条栏宽管住整个窗口。** 联系人行、每条气泡、输入框都居中在同一条栏上。任何偏离这条线的东西都会让窗口看起来没做完，不管零件本身多好。
- **两边都是气泡。** 用户侧着色，助手侧中性。
- **分组决定圆角。** 同一侧连续消息靠得近、换边隔开；**组的第一条**那个靠近发送者的角是尖的，组内的接缝是方的，组的最后一条收圆。三条各自带尾巴读起来是三个念头，而它们是一句话。
- **联系人行只有两个状态**：在线 / 正在输入…。多一个都会变成"界面声称知道她在干什么"，而它不知道。
- **`Warn` 颜色只留给"需要人"。** 正常活动不许用黄色。焦点环是 `accent`，也是它唯一非按下状态的出现。
- **快捷回复 chip 在气泡里**，点了等于你说那句话。
- 消息能带：markdown（行内样式、代码块、表格、列表）、文件、快捷回复。
- **空状态是一句话加一句提示**，没有插图替它们顶班。

具体的栏宽、间距、字号、圆角都在 `crates/odiva/src/style.rs`；这里只说规则，不复述数字。

## 调色板

`src/theme.rs` 里两个 `Theme::custom`：`dark()` 和 `light()`。六个基色，其余全由 iced 的 extended palette 推导，`ericed::style::Tokens` 再从那里取。所以改一个色就同时改了窗口、气泡、边框和 markdown 行内代码。

不用现成的编辑器主题：这是一个整天读的对话窗口，表面要中性安静，只有"可以动手"的东西才上强调色。紫底紫框那种开发者主题读起来像编辑器里塞了个聊天框。

深色是默认，理由是用场景不是口味：桌面上还开着编辑器和终端，一个亮窗口在那种场合是一盏照脸的灯。

## 依赖

- `iced` 的 `markdown` feature（`iced_widget/markdown`，基于 pulldown-cmark）：行内加粗/斜体/链接/行内代码、代码块、列表、表格都是现成的。
- `ericed`：`StyleExt` + `Tokens` 提供调色板；`Surface`/`Type`/`Act`/`Line`/`Shape` 是应用的视觉词汇表；`list::{Measured, Scroll, Slice}` 是窗口化列表。
- `chrono`：时间分隔线要知道读者所在时区和"今天是几号"，标准库没有时区。只在这一侧用。

## iced 的坑

踩过的三个坑各自在代码里写了一句，因为它们只有在紧挨着修法的地方才有用：

- 代码块气泡先 `styled` 再 `width(Fixed)` —— `Fill` 的子元素在 `Shrink` 里解析成 0 宽（`src/view.rs`）。
- 代码块背景要用自己的 `Surface::Code` 覆写，默认是给每个主题都一样的深色（`src/view.rs`）。
- 贴底不是自己算出像素目标再滚过去，而是问 iced 要"相对偏移 1.0"（`snap_to`）：表里的总高对没建过的行只是估算，算出来的目标会被 iced 按真实内容夹到别处，两个数轮流说话就是底部那阵频闪。与 `Scrollable::anchor_bottom()` 无关——`anchor_bottom` 改的是没得滚时拇指的位置（`src/lib.rs`）。

## 布局账本

窗口自己持有的状态只有四种数：每行的高度、总高、视口偏移、视口高度。它们一起回答三个问题。

**两个高度，别混。** `Measured::total()` 是表：建过的行是实测，没建过的是估算。`content_bounds().height()` 是 iced 真正布局出来的内容高度，滚动条和所有偏移都按它夹。只有后者可以被相信，所以表只决定"建哪些行"，不决定"视口在哪"（这条曾经反着写，代价就是底部的频闪）。

**只建该建的行。** `ericed::list::Measured` + `Scroll` 给出这一帧该建哪些槽位，`Slice::surround` 补上、下 spacer，让内容总高在滚动时保持不变。贴底时窗口取表的末端（`App::window_top`）：刚追加的那条因此在同一帧里被建出来、量到、画出来——少这一帧，底部会闪一下空白。

**高度从哪来。** 每行外面套一个 `sensor`，布局完就报自己的实际高度；在那之前用估算值。行高包含它上方那段间距（`App::gap_at`），估算和视图都从这一个函数取——早先估算漏了它，每行都少算 10~16px，逐行累加到底部就是"最后一条被切掉"。

**从上往下长。** 第一条消息贴着分隔线下面，后来的往上长，不留前导空白；内容不足一屏时就是这样，超过一屏则新消息在底部，`pinned` 按视口自己报来的偏移与内容高度判定，人往上翻就脱离，点"↓"重新归位。

**失败要说出来。** `CoreFailed` 渲染成输入框上方的一行 `Type::Error`，下一次发送时清掉。它是窗口里唯一不是气泡的文字——因为她可以决定不说话，窗口不能替她假装没出错。

常量与实现在 `src/lib.rs` 与 `src/model.rs`。

**一个诚实的残留。** 截图工具（`iced_test::screenshot`）只跑一帧布局，`sensor` 的消息不会在出图前送达，所以截图里的高度仍是估算值。真窗口第二帧就没有了。

## 时间

每条消息带 UTC 毫秒。窗口在间隔够长或跨天时插一条居中分隔线，措辞按"今天 / 昨天 / 周几 / 月日 / 年月日"选最近一层——这是本地日历的换算，所以用 `chrono`，且只在窗口这一侧。阈值与措辞在 `src/time.rs`。

## 窗口持有什么，不持有什么

不持有：对话本身。消息只经 `App::apply(CoreMessage)` 进入，`App::attached(Snapshot)` 是唯一的重建入口。

持有：布局（上面那四种数）、`Theme`、一个可选的时钟，以及连着 core 的两端。

这几样都不是对话，各自有"为什么在这里"的答案：

- **`Theme`**：markdown 组件要调色板作为**参数**，而 `view` 函数拿不到主题。所以主题存在 App 里——一处同时决定 iced 主题和 markdown 调色板，否则浅色主题会在行内代码上露馅。
- **时钟**：`with_clock(ms)` 冻结"现在"，让截图每次都是同一张。生产路径是 `chrono::Local::now()`。
- **`Wire`（`src/wire.rs`）**：`CoreHandle` 把人的动作送出去；`UnboundedReceiver<CoreMessage>` 归 subscription，第一条被 `App::subscription` 取走后变成 `Message::CoreReported`。没有 core 时两端都是空的，所以 `App::empty()` 在截图和协议测试里不需要通道。
- **`with_viewport(height)`**：首帧就要知道视口多高，才能决定"短对话贴底还是长对话留顶"。真窗口给它的是 `sensor`，测试和截图给它一个数。

## 已知缺口

- 图片、引用回复未做；语音不做。
- 长对话里第一屏之前的行始终没建过，高度只能停在估算上；表的总高因此与真实内容高度差一截。这不影响滚动和贴底（两者都只认视口报来的数），只影响滚动条的刻度——离真实比例可能有偏差。
- IME 只在真窗口里能验，截图路径不经过输入法。
