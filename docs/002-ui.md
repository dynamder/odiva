# 002 UI

一个普通的聊天窗口。三层带：联系人行、会话区、输入区。

## 规则

- **两边都是气泡。** 用户侧着色（`surface_selected`），助手侧中性（`surface`）。
- **靠近发送者的那个角是尖的**（5px vs 14px）。两个同色矩形靠这一下才像对话。
- **间距就是分组。** 同一侧连续消息间距 4px，换边 16px。不需要名字标签。
- **联系人行只有两个状态**：在线 / 正在输入…。多一个都会变成"界面声称知道她在干什么"，而它不知道。
- **`Warn` 颜色只留给"需要人"。** 正常活动不许用黄色。
- **快捷回复 chip 在气泡里**，点了等于你说那句话。
- 消息能带：markdown（含行内样式、代码块、表格）、文件、快捷回复。

## 依赖

- `iced` 的 `markdown` feature（`iced_widget/markdown`，基于 pulldown-cmark）：行内加粗/斜体/链接/行内代码、代码块、列表、表格都是现成的，只有代码块背景跟随主题。
- `ericed`：`StyleExt` + `Tokens` 提供调色板；`Surfaces`/`Type`/`Act` 是应用的视觉词汇表。

## 两个 iced 的坑（都踩过）

1. **`Scrollable::anchor_bottom()` 不是内容贴底。** 它改的是 `Scrollbar::alignment`（没得滚时拇指的位置）。真做贴底要 `sensor` 上报内容高度再算顶部 spacer，且流式时高度每帧在变会跳——所以现在顶部对齐。
2. **`Length::Fill` 的子元素放进 `Shrink` 父级会解析成 0 宽。** 一条气泡因此变成 30×250 的竖条，文字完全不见。修法：气泡内的文本不设 `Fill`，靠外层 `container().align_x()` 定位。

## 已知缺口

- 底部对齐未做（见坑 1）。
- 虚拟化列表未接（`ericed::list::Measured`）。
- 滚动策略只有状态位：`Pinned`/`Free` 的 offset 还没接。
- 图片、引用回复未做；语音不做。
- IME 只在真窗口里能验，截图路径不经过输入法。
