# 002 UI

一个普通的聊天窗口。三层带：联系人行、会话区、输入区。

## 规则

- **一条栏宽管住整个窗口。** 联系人行、每条气泡、输入框都居中在同一条 700px 的栏上。任何偏离这条线的东西——比如名字贴在窗口边缘而气泡从 170px 开始——都会让窗口看起来没做完，不管零件本身多好。
- **两边都是气泡。** 用户侧着色（`surface_selected`），助手侧中性（`surface`）。
- **分组决定圆角。** 同一侧连续消息间距 3px、换边 16px；**组的第一条**那个靠近发送者的角是尖的（5px），组内的接缝是 8px，组的最后一条收圆。三条各自带尾巴读起来是三个念头，而它们是一句话。
- **联系人行只有两个状态**：在线 / 正在输入…。多一个都会变成"界面声称知道她在干什么"，而它不知道。
- **`Warn` 颜色只留给"需要人"。** 正常活动不许用黄色。焦点环是 `accent`，也是它唯一非按下状态的出现。
- **快捷回复 chip 在气泡里**，点了等于你说那句话。
- 消息能带：markdown（行内样式、代码块、表格、列表）、文件、快捷回复。
- **空状态是一句话加一句提示**，没有插图替它们顶班。

## 调色板

`src/theme.rs` 里两个 `Theme::custom`：`dark()` 和 `light()`。六个基色，其余全由 iced 的 extended palette 推导，`ericed::style::Tokens` 再从那里取。所以改一个色就同时改了窗口、气泡、边框和 markdown 行内代码。

不用现成的编辑器主题：这是一个整天读的对话窗口，表面要中性安静，只有"可以动手"的东西才上强调色。紫底紫框那种开发者主题读起来像编辑器里塞了个聊天框。

深色是默认，理由是用场景不是口味：桌面上还开着编辑器和终端，一个亮窗口在那种场合是一盏照脸的灯。

## 依赖

- `iced` 的 `markdown` feature（`iced_widget/markdown`，基于 pulldown-cmark）：行内加粗/斜体/链接/行内代码、代码块、列表、表格都是现成的。
- `ericed`：`StyleExt` + `Tokens` 提供调色板；`Surface`/`Type`/`Act`/`Line`/`Shape` 是应用的视觉词汇表。

## 三个 iced 的坑（都踩过）

1. **`Scrollable::anchor_bottom()` 不是内容贴底。** 它改的是 `Scrollbar::alignment`（没得滚时拇指的位置）。真做贴底要 `sensor` 上报内容高度再算顶部 spacer，且流式时高度每帧在变会跳——所以现在顶部对齐。
2. **`Length::Fill` 的子元素放进 `Shrink` 父级会解析成 0 宽。** 一条气泡因此变成 30×250 的竖条，文字完全不见。修法：气泡内的文本不设 `Fill`，靠外层 `container().align_x()` 定位。同样的问题让代码块气泡整个塌掉——markdown 的块级 item 是 `Fill`，所以带代码块/表格的气泡要**先 `styled` 再 `width(Fixed)`**，`max_width` 不够（它不改子元素的 limits）。
3. **markdown 的代码块背景是 `container::dark`，对每个主题都一样。** 浅色主题下就是黑底深字，几乎读不了。修法是实现一个只覆写 `code_block` 的 `markdown::Viewer`，用本窗口的 `Surface::Code`（canvas 底、无描边——气泡和块各有一道边框就是框里套框）。

## 已知缺口

- 底部对齐未做（见坑 1）。
- 虚拟化列表未接（`ericed::list::Measured`）。
- 滚动策略只有状态位：`Pinned`/`Free` 的 offset 还没接。
- 图片、引用回复未做；语音不做。
- 时间戳：现在是一条常量分隔线，等 core 开始报告时间才能真的按天分段。
- IME 只在真窗口里能验，截图路径不经过输入法。
